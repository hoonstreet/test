# 이사해드림 CMS

이사해드림의 지역·서비스별 홈페이지와 관리자 콘텐츠 편집 기능을 제공하는 Spring Boot CMS입니다.

## 현재 포함된 기능

- 블루 계열 벤토 그리드 반응형 홈페이지
- 14개 시·구, 132개 하위 동, 6개 이사 서비스 초기 데이터
- 시·구 84개와 동 792개를 합친 총 876개 지역·서비스 랜딩페이지
- `시·구 → 동 → 서비스` 계층형 탐색과 동 단위 서비스 허브
- 대표번호 `010-5297-2459`와 카카오톡 상담 연결
- 관리자 로그인, 공통 연락처 설정, 페이지별 SEO 콘텐츠 편집
- 지역별 876개 조합의 `미작성·작성중·공개` 진행률과 서비스/상태 필터

- PostgreSQL 17 및 Spring Boot 3.5.6 Docker Compose 구성
- 기존 서버 데이터를 그대로 유지하는 고정 PostgreSQL 볼륨 `isahaedream-site_postgres_data`
- 무결성 검증·복구 전 자동 안전 백업을 포함한 PostgreSQL 백업·복구 스크립트
- 애플리케이션 포트는 `127.0.0.1:8080`에만 바인딩
- PostgreSQL 포트는 호스트에 공개하지 않음

## 보안 원칙

- `.env`는 Git에 커밋하지 않습니다.
- 관리자 비밀번호와 DB 비밀번호는 서로 다른 12자 이상의 값으로 설정합니다.
- 비밀번호, API 토큰, 개인키는 채팅이나 로그에 출력하지 않습니다.
- `SEARCH_INDEX_ENABLED`는 도메인과 고유 콘텐츠가 준비될 때까지 `false`를 유지합니다.
- 현장 사진은 번호판, 인물, 기존 전화번호와 메타데이터를 정리한 웹용 복사본만 공개합니다.

## 지역 키워드 고정 정책

- 검색 대상 지역은 초기 데이터에 등록된 `14개 시·구 + 132개 하위 지역`만 사용합니다.
- 이 지역과 6개 서비스의 조합인 876개 외에 새 지역 키워드, URL 또는 사이트맵 항목을 만들지 않습니다.
- 예를 들어 승인된 키워드는 `중곡동`이며 `중곡1동`, `중곡2동`, `중곡3동`, `중곡4동`은 SEO 제목,
  검색 설명, 페이지 제목, URL 키워드로 사용하지 않습니다.
- 세부 행정구역은 방문자에게 필요한 설명일 때 본문에만 사용할 수 있습니다.
- 지역 목록 변경은 자동화하지 않으며 사용자의 명시적인 확인 후에만 수정합니다.

## 로컬 테스트

Java 21과 Maven 3.9 이상이 필요합니다.

```bash
mvn test
```

## Docker 실행

`.env.example`을 참고해 서버 안에서만 `.env`를 만들고 실제 비밀번호를 입력합니다.

```bash
docker compose build
docker compose up -d
docker compose ps
curl -I http://127.0.0.1:8080/
```

## 신규 Lightsail 서버 첫 배포

배포 스크립트는 공인 IP가 신규 서버 `15.164.87.34`와 일치할 때만 실행됩니다. 기존 운영 서버
`3.38.19.90`에서는 실행을 거부합니다.

```bash
chmod +x deploy/first-deploy.sh
./deploy/first-deploy.sh
```

스크립트는 관리자 비밀번호를 화면에 표시하지 않고 입력받으며, 데이터베이스 비밀번호를 서버에서
무작위로 생성합니다. `.env`가 이미 있으면 덮어쓰지 않습니다. 도메인이 준비될 때까지
`SEARCH_INDEX_ENABLED=false`를 유지합니다. 관리자 비밀번호는 12자 이상으로 만들고 영문, 숫자와
`. _ @ % + = : -` 문자만 사용합니다.

첫 배포가 정상 종료되면 `backups/`에 초기 데이터베이스 백업을 자동으로 남깁니다.

## 데이터베이스 백업과 복구

콘텐츠를 수정하거나 배포하기 전에 서버의 프로젝트 폴더에서 다음 명령을 실행합니다.

```bash
bash deploy/backup-db.sh
```

백업은 `backups/isahaedream_YYYYMMDDTHHMMSSZ.dump`와 SHA-256 검증 파일로 저장됩니다.
`backups/`는 Git에 포함되지 않으므로 중요한 백업은 서버 밖의 암호화된 저장소에도 복사해야 합니다.

복구는 현재 데이터베이스를 교체하는 작업입니다. 지정한 백업의 무결성을 확인하고, 현재 데이터를 한 번 더
자동 백업한 뒤 `RESTORE`를 직접 입력해야 시작됩니다.

```bash
bash deploy/restore-db.sh backups/isahaedream_YYYYMMDDTHHMMSSZ.dump
```

정기 백업 자동화는 서버 배포 후 저장 주기와 외부 복사 위치를 확정한 뒤 설정합니다.
